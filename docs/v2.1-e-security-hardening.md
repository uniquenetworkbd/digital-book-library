# v2.1-E — Content Security Policy & Security Hardening

## Baseline
- CSP is deployed as an HTML meta policy on the static pages.
- Client-side input sanitization helper is exposed as `DigitalBookLibrarySecurity.sanitizeHTML`.
- No server-side security headers are assumed because the platform targets GitHub Pages.

## CSP policy
- `default-src 'self'`
- `script-src 'self'`
- `style-src 'self' 'unsafe-inline'`
- `img-src 'self' data: blob:`
- `connect-src 'self' https://api.telegram.org`
- `worker-src 'self'`

## Important limitation
Meta CSP is weaker and less flexible than an HTTP response-header CSP. It does not replace server-side headers where those are available.

## Validation rule
Before enabling stricter directives, audit inline scripts, dynamic imports, workers, image sources, fetch destinations, and service-worker behavior so existing V2 functionality is not broken.
